# Ритм — симулятор продакт-менеджера

Одностраничная браузерная игра-тренажёр для продакт-менеджеров. Без зависимостей, без сборки, без бэкенда: весь продукт — это `index.html`.

Автор: Ruslan Sharipov. Два языка: русский и английский.

## Публикация

GitHub Pages из ветки `main`, корень репозитория: https://sharipovrus.github.io/pm-sim/ (репозиторий `SharipovRus/pm-sim`). Push в `main` выкатывает сайт сам, сборка Pages занимает около минуты.

- `/` — игра. Мета-теги и `og.png` русские.
- `/en/` — ссылка для англоязычных постов: английские мета-теги и `og-en.png`, JS-редирект на `/?lang=en`. Краулеры JS не выполняют и берут превью с этой страницы.

## Архитектура

Всё в `index.html`, порядок сверху вниз:

- `<style>` — токены темы в `:root`, тёмная тема через `prefers-color-scheme` и `[data-theme]`. Цвета берутся только из переменных. Кнопка ☀/☾ в шапке ставит `data-theme` и сохраняет выбор (`ritm-theme`); маленький скрипт в `<head>` применяет его до первой отрисовки. Canvas-картинки (карточка, сертификат) всегда светлые.
- `SCEN` — массив из 35 кейсов. У каждого: домен (`disc` / `prio` / `metr` / `exp`), персонаж-отправитель, текст, варианты с качеством (`best` / `ok` / `bad`), эффекты на метрики, отложенные эффекты, разбор и принцип. Кейс с `dilemma:true` — дилемма: в нём ровно два варианта `best` с разными трейд-офами, `altBest()` показывает второй путь вместо «Сильнее».
- Варианты внутри кейса держи примерно одной длины (±20%), а слабые — правдоподобными. Иначе верный ответ угадывается по длине.
- `CHAL` — 17 генераторов задач. В задачах на знание по 5 вариантов формулировки (в модели Кано — 8). Каждый возвращает готовый объект задачи со случайными числами, правильным ответом и объяснением. Типы: `number` (ввод числа с допуском) и `choice` (выбор варианта).
- `GLOSS` — 58 терминов для шпаргалки и кликабельных подсказок. `annotate()` подсвечивает термины в уже отрисованном DOM, обходя текстовые узлы.
- Экономическая модель: `derive()` считает производные метрики, `closeMonth()` делает месячный тик (удержание, органика, платные установки, выручка, кэш, дрейф морали и доверия). Старт — `START_CASH` ($350k). После месяца `REVIEW.month` (5) инвестор даёт второй транш: полный при MRR ≥ `REVIEW.full` × стартовый, половину при ≥ `REVIEW.half`, иначе ничего. Пороги подобраны прогоном ботов: идеальная игра почти всегда получает транш, случайная примерно в половине партий банкротится.
- Решения в итогах месяца (блок «Твой ход»): маркетинговый бюджет и `m.debtShare` — доля команды на техдолг (0–40%). Константы в `DEBT_WORK`: долг сам растёт на `drift` в месяц, каждые 10% команды снимают `paydown/10`, органика падает на `organic × доля`, выше 50 долг режет retention на `penalty` за пункт. Баланс подобран ботами: 10–20% лучше, чем 0% или 40%.
- Лидерборд: Supabase (проект `xcqnfeebhxjarxcsjrop`, Singapore; репозиторий к нему не привязан, миграции применяются вручную через SQL Editor), схема в `supabase/migrations/` (таблица `leaderboard` закрыта RLS, наружу только функции `submit_score` и `top_scores`). В `index.html` константы `LB.url` / `LB.key` (publishable-ключ, он публичный); пустые — лидерборд скрыт. Игрок — ник и необязательная ссылка на LinkedIn, секретный токен лежит в `localStorage` (`ritm-player`), в базе только его sha256. Ссылка `?claim=<token>&n=<ник>&li=<ссылка>` переносит игрока на другое устройство (кнопка «Ссылка для другого устройства» после регистрации); параметры сразу убираются из адресной строки. `submit_score` проверяет ник, ссылку, что счёт сходится с `s1/s2/biz` по формуле из `finalScore()`, и хранит лучший результат. Пороги грейдов в `grade_for()` должны совпадать с `finalScore()`.
- Сертификат: только за полные 10 месяцев без банкротства (`certEligible()`). `issue_certificate()` в Supabase (миграция `..._certificates.sql`) проверяет имя и счёт и выдаёт публичный ID; `drawCert()` рисует PNG 1600×1131. Проверка — тот же `index.html` с `?cert=ID` (`CERT_VIEW`, `renderCertView()`); `/en/` пробрасывает параметры. Кнопка LinkedIn «Add to profile» открывает форму сертификата с параметрами, рядом поля для ручного копирования (LinkedIn может их не подхватить). Перед рисованием на canvas шрифты грузятся с `FONT_SAMPLE`, иначе кириллица уходит в запасной шрифт.
- Карточка результата: `drawCard()` рисует PNG 1200×630 на canvas, финальный экран показывает её с кнопками «поделиться / LinkedIn / скопировать».
- Аналитика: `GC_CODE` — код сайта GoatCounter (`sharipovrus`, статистика на https://sharipovrus.goatcounter.com). Пустой код выключает счётчик, на localhost он не работает. Путь страницы пишется как `/pm-sim/` или `/pm-sim/?lang=en` по фактическому языку. `/en/` перед редиректом кладёт `document.referrer` в `sessionStorage` (`ritm-ref`), чтобы источник перехода не терялся. `track(event)` шлёт события `start`, `review-*`, `finish`, `bust`, `share-*` с суффиксом языка.
- Рендер: функции `renderX()` собирают HTML строкой, состояние в глобальной `S`, сохранение в `localStorage`.

Языки:

- `LANG` выбирается так: параметр `?lang=`, потом сохранённый выбор (`ritm-lang`), потом язык браузера. `L(ru, en)` возвращает строку текущего языка. `setLang()` перерисовывает всё, включая открытую шпаргалку.
- Русский контент лежит в `SCEN` и `GLOSS`, английский — в оверлеях `SCEN_EN` и `GLOSS_EN` с теми же ключами. `scenL(id)` и `glossL(g)` склеивают их под текущий язык. Новый кейс или термин добавляй в оба места.
- Константы с текстом (`DOMAINS`, `PEOPLE`, `QUAL`, `FX_META`, `CHAL_BONUS`) пересоздаются в `i18nConsts()` при смене языка.
- Тексты в `CHAL` обёрнуты в `L()` прямо в генераторах. `genChal()` вызывает генератор дважды, для `ru` и для `en`, с одним и тем же seed, поэтому числа совпадают. Отсюда правило: количество вызовов `rnd/ri/pick/shuffle` не должно зависеть от языка, а массивы в `L([...],[...])` должны быть одинаковой длины.
- В `S` хранится не текст, а ссылки: id кейса и индекс варианта в `log` и `queue`, тексты задачи в обоих языках в `cur.chal.txt`. Поэтому язык можно сменить посреди месяца.
- Форматирование `int/dec/pct` зависит от языка: в ru десятичная запятая, в en точка. В английском режиме ввод ответа понимает запятую как разделитель тысяч.
- Варианты кейсов перемешиваются на каждый месяц (`S.cur.order`). Клавиши 1–5 выбирают вариант по позиции на экране, а не по индексу.

Правила, которые легко случайно нарушить:

- Варианты ответа (`.opt`) намеренно исключены из `annotate()` — иначе клик по термину перехватывает выбор ответа.
- `index.html` в этом репозитории — полноценный документ с `<head>`. Версия, опубликованная как артефакт Claude, отличается: там `<head>` добавляется платформой.
- Внешние загрузки: шрифты (Google Fonts) и, если задан `GC_CODE`, скрипт GoatCounter. Другие внешние скрипты не добавляй.

## Идеи развития

По убыванию ценности:

1. **Синонимы метрик.** В карточку термина добавить строку «как ещё называют» (ARPU / ARPPU, CAC / CPA / CPI, LTV / CLV, retention / возвращаемость) и режим-квиз «одно и то же или разное?». Это главный смысл тренажёра: на интервью метрики называют по-разному.
2. **Быстрый режим.** 10 задач подряд с таймером, без симуляции — размяться перед собеседованием.
3. **Второй сценарий — мобильная игра.** IAP вместо подписки, ARPDAU, D1/D7/D30, окупаемость когорты по дням.
4. **Уровни сложности.** Про-режим: без вариантов ответа, числовой ввод, кейсы без явно верного варианта.
5. **Вынести контент в JSON.** `scenarios.json`, `challenges.json`, `glossary.json` — чтобы добавлять кейсы, не трогая код.

## Проверка после изменений

Открой `index.html` в браузере и в обоих языках (RU и EN) пройди хотя бы один месяц целиком: ситуация, задача, итоги месяца. Проверь консоль на ошибки, клик по термину, кнопку «Шпаргалка» и ширину экрана 390px — горизонтального скролла быть не должно.
