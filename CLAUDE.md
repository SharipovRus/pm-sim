# Ритм — симулятор продакт-менеджера

Одностраничная браузерная игра-тренажёр для продакт-менеджеров. Без зависимостей, без сборки, без бэкенда: весь продукт — это `index.html`.

Автор: Ruslan Sharipov. Язык интерфейса и контента — русский.

## Задача на сейчас: опубликовать на GitHub Pages

Выполни по шагам и отчитайся о результате.

1. Узнай github-логин пользователя: `gh api user --jq .login`. Если `gh` не авторизован — выполни `gh auth login` и дождись, пока пользователь пройдёт авторизацию в браузере. Если `gh` не установлен, скажи об этом и предложи установку, не придумывай обходных путей.
2. В `index.html` замени обе подстроки `USERNAME` на реальный логин. Это мета-теги `og:image` и `og:url` — без них превью ссылки в LinkedIn не отрисуется. Если имя репозитория отличается от `pm-sim`, поправь и его в этих же двух URL.
3. В `README.md` замени `USERNAME` в ссылке «Играть».
4. `git init`, `git add .`, коммит с сообщением `Ритм: браузерный симулятор продакт-менеджера`.
5. Создай публичный репозиторий и запушь: `gh repo create pm-sim --public --source=. --remote=origin --push`.
6. Включи Pages: `gh api -X POST repos/{owner}/pm-sim/pages -f source[branch]=main -f source[path]=/` (если ответ 409 — Pages уже включены, это не ошибка).
7. Подожди пару минут и проверь, что страница отдаёт 200: `curl -sSI https://<логин>.github.io/pm-sim/ | head -1`. Проверь отдельно, что `og.png` тоже отдаётся.
8. Выведи пользователю финальную ссылку одной строкой.

Если какой-то шаг не проходит, не обходи его молча — скажи, что именно сломалось.

## Архитектура

Всё в `index.html`, порядок сверху вниз:

- `<style>` — токены темы в `:root`, тёмная тема через `prefers-color-scheme` и `[data-theme]`. Цвета берутся только из переменных.
- `SCEN` — массив из 17 кейсов. У каждого: домен (`disc` / `prio` / `metr` / `exp`), персонаж-отправитель, текст, варианты с качеством (`best` / `ok` / `bad`), эффекты на метрики, отложенные эффекты, разбор и принцип.
- `CHAL` — 18 генераторов задач. Каждый возвращает готовый объект задачи со случайными числами, правильным ответом и объяснением. Типы: `number` (ввод числа с допуском) и `choice` (выбор варианта).
- `GLOSS` — 58 терминов для шпаргалки и кликабельных подсказок. `annotate()` подсвечивает термины в уже отрисованном DOM, обходя текстовые узлы.
- Экономическая модель: `derive()` считает производные метрики, `closeMonth()` делает месячный тик (удержание, органика, платные установки, выручка, кэш, дрейф морали и доверия).
- Рендер: функции `renderX()` собирают HTML строкой, состояние в глобальной `S`, сохранение в `localStorage`.

Правила, которые легко случайно нарушить:

- Варианты ответа (`.opt`) намеренно исключены из `annotate()` — иначе клик по термину перехватывает выбор ответа.
- `index.html` в этом репозитории — полноценный документ с `<head>`. Версия, опубликованная как артефакт Claude, отличается: там `<head>` добавляется платформой.
- Внешних скриптов нет и не нужно. Шрифты — единственная внешняя загрузка (Google Fonts).

## Идеи развития

По убыванию ценности:

1. **Синонимы метрик.** В карточку термина добавить строку «как ещё называют» (ARPU / ARPPU, CAC / CPA / CPI, LTV / CLV, retention / возвращаемость) и режим-квиз «одно и то же или разное?». Это главный смысл тренажёра: на интервью метрики называют по-разному.
2. **Быстрый режим.** 10 задач подряд с таймером, без симуляции — размяться перед собеседованием.
3. **Карточка результата для шеринга.** Генерировать картинку с грейдом и метриками.
4. **Второй сценарий — мобильная игра.** IAP вместо подписки, ARPDAU, D1/D7/D30, окупаемость когорты по дням.
5. **Уровни сложности.** Про-режим: без вариантов ответа, числовой ввод, кейсы без явно верного варианта.
6. **Вынести контент в JSON.** `scenarios.json`, `challenges.json`, `glossary.json` — чтобы добавлять кейсы, не трогая код.
7. **Счётчик посещений** (GoatCounter / Plausible), две строки в `<head>`.

## Проверка после изменений

Открой `index.html` в браузере и пройди хотя бы один месяц целиком: ситуация, задача, итоги месяца. Проверь консоль на ошибки, клик по термину, кнопку «Шпаргалка» и ширину экрана 390px — горизонтального скролла быть не должно.
